# ProcessPilot 30-Skill Runtime

本目录实现 A14 项目的单 Agent、多 Skill 运行时。30 个 Skill 不是 30 个独立聊天机器人，而是由总控 Agent 按目标动态选择的工业能力单元。

## 运行契约

- 输入：`run_id`、`scenario`、`equipment_id`、`dataset_ref`、`objective`、`parameters`、`constraints`
- 输出：`status`、`metrics`、`artifacts`、`evidence`、`warnings`、`suggested_next_skills`
- 编排：用户目标直接命中 Skill，规划器递归补齐依赖，再按注册顺序形成 DAG 的拓扑执行序列。
- 证据：数据治理、动态优选、辨识和寻优类 Skill 均读取当前流水线真实 `snapshot`，不在前端伪造指标。
- 审计：每次执行写入 `runtime/agent_skill_runs/<skill_run_id>.json`，该目录属于运行产物，不进入代码压缩包。

## 文件职责

- `catalog.py`：30 个 Skill 的名称、类别、触发词、依赖、处理器与输入输出协议。
- `runtime.py`：实体/参数抽取、能力匹配、依赖规划、统一执行和运行记录持久化。
- `core/agent_api.py`：技能目录、规划、执行、详情与事件接口。

算法继续复用项目已有的标准化、清洗、动态段筛选、时滞、共线性、ARX 和闭环寻优实现。Skill Runtime 负责“理解—选择—编排—执行—解释—审计”，避免复制算法或产生两套不一致结果。

## 专家问题覆盖

`core/services/expert_qa.py` 提供专业问法覆盖层。目前覆盖 21 类专家问题，包括采样与混叠、SNR、持续激励、候选段降级建模、时序泄漏、残差、稳定性、频率特性、时滞、共线性、因果边界、泛化、阶次、寻优候选、审计复现、上线安全、跨场景迁移、模型漂移、缺失异常清洗、字段单位校验和交付审计。回答必须消费已命中专业 Skill 对应的当前任务指标，并区分“当前任务已有证据”和“仍需补充验证”，禁止把示例图、互相关或共线性降维包装成生产因果结论。

调度器先解析 `mode/topics/requested_metrics/safety`，再使用专业主题矩阵召回候选 Skill，并为候选记录相关性分数和入选原因。专家只读问题使用最小 Skill 集，不根据“测试集”“工况”等宽泛名词误触发数据生成或动态检测；执行型指令才递归补齐算法依赖。复合问题允许同时命中多个主题，回答合成器逐项覆盖并生成证据缺口清单。

执行门禁只接受“重新执行、重新运行、重跑、请执行”等明确动作，不会把“哪些参数需要重新辨识”一类分析问题误判为重跑。回答合成器对时滞、VIF、训练/测试指标、AIC/BIC 和候选轮次执行存在性检查；阶段产物缺失时必须显示“未保存/无法判断”，禁止用 `0` 代替缺失证据。

## 2026-09-09 验证协议修正

- 中控执行入口为 `validated_pipeline_bundle`：真实算法在本地流水线内执行，Skill记录分别标记 `planned`、`read`、`unavailable`；取证不代表再次执行算法。存在缺证据项时总体状态为 `partial`。
- 先按时间固定60%/20%/20%分区，各区单独因果清洗。输入仅前向填充最多6点，缺失/异常输出不作为真值。不得通过更细的重采样间隔制造训练输出。
- SNR使用稳健二阶差分白噪声代理估计；逐窗口逐变量保存信号功率、噪声功率和样本数。阈值10 dB仅是筛选配置，不等同于仪表标定或持续激励证明。
- 因果时滞、共线性和模型系数只从训练数据学习，跨时间断档不构造滞后特征。AR/ARX的1/2/3阶及所有参数候选使用相同验证目标哈希。
- 每轮参数、训练CSV、实际行数与训练覆盖率必须对应。选定后冻结模型，独立测试只执行一次；报告单步、持续值基线、10步条件预测、条件自由仿真及残差ACF。
- 高单步R²不能覆盖基线改善不足、AR-only胜出、极点不稳定或自由仿真失败。白噪声显著性检验、残差输入独立性、参数区间和外部炉次验证仍明确列为证据缺口。
- 窗口数量与阶次由验证搜索选择；目前中控支持采样周期和最大时滞参数，未支持的显式参数会拒绝执行，禁止默默忽略。
- 通过 `07_delivery/audit_manifest.json`核对输入/产物/代码SHA-256与依赖版本。旧任务不会被覆盖，需重跑才获得新版证据。
