# 工业数据接入、模型训练与四份 CSV 验收

## 问题结论

上传接口原先在字段标准化已经判定 `reject` 后仍继续执行清洗和建模。下游收到缺少时间轴或被控输出的残缺数据后抛出异常，前端只显示“流水线执行失败”，用户看不到已经生成的字段诊断。

本次修复让流水线在标准化拒绝时正常结束为 `needs_review`，保留字段映射、缺失字段、类型错误和场景置信度，跳过不具备输入条件的下游阶段。接口返回 HTTP 201 和 `ok: true`，前端显示“数据未进入建模”及具体原因。日期转换也会在默认格式失败较多时尝试日优先格式，解决 `DD/MM/YYYY` 时间列的大量误判。

## 验收标准与结果

- 四个真实文件均完成流水线调用且未抛出异常；三个不满足契约的文件返回 `needs_review`，钢铁能耗文件完整结束为 `completed`。
- 钢铁能耗验收运行 `20260909_210532_aa65115c`：质量分 87.15，清洗 35,040 行，选出 771 个候选动态段。
- 钢铁能耗独立测试：AR 模型 R² 0.88182、RMSE 11.69399；AR 基线胜出，因此报告明确阻断软测量和闭环控制结论。
- 不满足字段契约的数据不会进入清洗、辨识或寻优。
- 不透明位号不会再根据字符相似度映射为布尔质量码。
- 人工映射支持选择场景、指定标准字段、明确忽略字段，并把覆盖值保存在运行快照中后重新执行。
- 前端生产构建通过。

## 公开数据与训练验收

钢铁能耗场景来自 UCI 数据集 851。官方下载压缩包 SHA-256 为 `d82d28b33780ff1582507fcf08ae764ff648af459d58234370c551e62aadeaef`；其中 CSV 的 SHA-256 为 `9b1cee6f9cb9cd9df2b95814ca90a9a2ff15b7f5f1fba0fae3c643e82072eacc`，与用户提供文件完全一致。许可证为 CC BY 4.0，原始数据不重复提交到仓库。

模型版本 `e309e8dc03a8` 使用 6,128 条基础样本、1,188 条审核通过的外部术语样本和 2,152 条仅从训练分组产生的格式增强样本。发布门禁结果：隔离测试 Top-1 100%、Top-3 100%；严格别名冷启动 Top-1 90.19%、Top-3 96.63%、相关字段接收召回率 94.59%；108 条无关测试样本的误接收率为 0%；直接语义冲突 0；保序覆盖率 97.15%。

训练数据审计的分组交叉验证准确率为 81.36%，期望校准误差为 44.36%，说明陌生工厂术语仍需拒识和人工复核。该指标不会被较高的模板别名测试分数掩盖。

## 数据继续建模所需补充

`vapor-pressure.csv` 需要专门的稀疏标签建模流程，不能把 98.76% 的目标缺失直接插值成真值。还需确认装置类型、字段单位、采样周期含义和目标化验来源。

两个 xinan 文件需要工艺位号字典，至少明确时间、被控输出、操纵量、扰动量、单位和合理范围。仅凭 `PT_`、`TE_`、`FT_` 等位号前缀自动猜测会造成错误映射。

`Steel_industry_data.csv` 现已由独立的“钢铁工业能源监测”场景处理。当前数据只证明历史能耗可以做离线时间序列预测；它没有可操纵控制量、联锁约束或现场干预证据，因此不能据此声称可做闭环 APC。

公开数据训练不能替代工厂现场资格确认。投产前仍需提供位号表、单位和量程、仪表校准与质量码、工况边界、不同时间段冻结外部测试集、报警联锁、回退策略、影子运行和工艺/自控人员签字。
