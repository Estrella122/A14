# CSV 上传故障修复与验收

## 问题结论

上传接口原先在字段标准化已经判定 `reject` 后仍继续执行清洗和建模。下游收到缺少时间轴或被控输出的残缺数据后抛出异常，前端只显示“流水线执行失败”，用户看不到已经生成的字段诊断。

本次修复让流水线在标准化拒绝时正常结束为 `needs_review`，保留字段映射、缺失字段、类型错误和场景置信度，跳过不具备输入条件的下游阶段。接口返回 HTTP 201 和 `ok: true`，前端显示“数据未进入建模”及具体原因。日期转换也会在默认格式失败较多时尝试日优先格式，解决 `DD/MM/YYYY` 时间列的大量误判。

## 验收标准与结果

- 四个真实文件均通过上传 API 返回 HTTP 201。
- 四个响应均包含标准化诊断、源数据行列数和人工复核原因。
- 四个响应的 `error` 均为 `null`。
- 不满足字段契约的数据不会进入清洗、辨识或寻优。
- `DD/MM/YYYY HH:mm` 日期解析测试通过。
- 后端新增回归测试 2 项，全部通过。
- 前端生产构建通过。

## 数据继续建模所需补充

`vapor-pressure.csv` 需要专门的稀疏标签建模流程，不能把 98.76% 的目标缺失直接插值成真值。还需确认装置类型、字段单位、采样周期含义和目标化验来源。

两个 xinan 文件需要工艺位号字典，至少明确时间、被控输出、操纵量、扰动量、单位和合理范围。仅凭 `PT_`、`TE_`、`FT_` 等位号前缀自动猜测会造成错误映射。

`Steel_industry_data.csv` 适合能耗预测或负荷分类，不具备当前工程内六类过程 APC 模板所需的温度、流量、压力等输入输出关系。若要建模，应新增“工业能耗”场景及明确预测目标，而不是强行套用锅炉或加热炉模板。
